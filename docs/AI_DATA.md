# AI-накопитель и AI-код: файлы, данные, логика

> Задача 4: **каждый час** система делает «анализ» (снимок прогноза + всех метрик),
> складывает в базу. Когда набираются **сутки** — складывает суточную сводку,
> когда **месяц** — месячную. Так база слоями накапливает материал для будущего AI.
> Дисклеймер: вероятность ≠ гарантия, проект образовательный.

---

## 1. Файлы: что есть и для чего

| Файл | Роль |
|---|---|
| `server/accum.mjs` | **Часовой накопитель.** Снимает часовые снапшоты в SQLite, строит суточные и месячные сводки, отдаёт состояние и ряды через API. Запускается из `server/index.mjs` (`startAccumulator`). |
| `server/store.mjs` | SQLite (`node:sqlite`) и таблицы свечей. Таблицы AI (`ai_snapshots`, `ai_rollup_daily`, `ai_rollup_monthly`) создаёт `accum.mjs` (идемпотентно). База: `data/market.db`. |
| `server/analysis.mjs` | Пул worker-потоков: прогноз (раз в 60 с) и walk-forward бэктест. Отсюда `accum.mjs` берёт `probUp/confidence/hitRate`. |
| `server/index.mjs` | HTTP + WS хаб. Подключает `/api/ai/*`, дергает `startAccumulator()` и передаёт FNG в `setAux`. |
| `server/exchange.mjs` | Binance/Bybit REST+WS, статистика цены, funding/OI, дисбаланс стакана. |
| `server/history.mjs` | Загрузка истории свечей (биржа + CoinGecko запас). |
| `server/worker.mjs` | Дочерний поток: тяжёлые расчёты (поиск аналогов, бэктест), чтобы UI не тормозил. |
| `lib/analyze.ts` | **Единое ядро анализа** (индикаторы, DTW-поиск, ансамбль, бэктест). Next компилирует как TS, сервер — как `lib/analyze.mjs` (генерит `tools/build-core.mjs`). |
| `components/ai/engine.ts` | **Твоё место для AI-кода**: функция `runAI(input)` → вердикт. Пока заглушка (`null`). |
| `components/views/AiView.tsx` | **Окно «AI»**: состояние базы, почасовая кривая вероятности, суточные и месячные сводки, панель движка. |
| `components/views/ForecastView.tsx` | Вкладка «Прогнозы»: ансамбль, веса, горизонты, гистограмма, риск-факторы, панель AI, веер. |
| `env.example` | Шаблон окружения (скопируй в `.env.local`; `.env*` в gitignore — секреты не утекают). |
| `docs/AI_DATA.md` | Этот файл: схема данных, логика, API-контракт, промт для модели. |

## 2. Три уровня данных (как в ТЗ)

### hourly → `ai_snapshots` (сырые часовые снапшоты, до 24/сутки)

Ключ: `(symbol, ts)`, `ts` — граница часа в **UTC**. UPSERT (при рестарте текущий час не дублируется).

| Поле | Откуда | Смысл |
|---|---|---|
| `price` | `state.stats[sym].price` (Binance/Bybit) | цена на момент часа |
| `probUp/probDown/probFlat` | ансамбль (`analysis.forecasts`) | вероятности исхода |
| `confidence` | ансамбль | уверенность модели 0..1 |
| `rsi` | `rsi()` из `lib/analyze.ts` по часовым свечам | перекупленность 0..100 |
| `volAnn` | `realizedVol()` | годовая волатильность % |
| `fng` | alternative.me (через `setAux`) | Fear & Greed 0..100 |
| `imbalance` | дисбаланс топ-20 стакана | −1..+1 (плюс = bid) |
| `funding`, `oiChange` | Bybit perp | перекос позиций |
| `horizonDays`, `analogs`, `bestLabel`, `bestSim` | прогноз | горизонт и лучший аналог |
| `hitRate`, `baseline` | последний бэктест | историческая точность и «всегда вверх» |

### daily → `ai_rollup_daily` (суточные сводки, 1/сутки)

`n` (часовых точек в дне), средние `probUpAvg/probDownAvg/confAvg/rsiAvg/fngAvg/imbalanceAvg/fundingAvg/hitRate/baseline`,
`priceClose` — цена последнего часа дня.

### monthly → `ai_rollup_monthly` (месячные сводки, 1/месяц)

Из суточных: `n` (всех часовых), `days` (сколько суток реально данными),
средние за месяц, `priceClose`, `hitRate`, `baseline`.

## 3. Логика накопления

1. **Каждый час** (`startAccumulator`, интервал `AI_SNAPSHOT_INTERVAL_MS`, по умолчанию 1 час):
   `snapshotAll()` → для каждой из 8 монет UPSERT-строка в `ai_snapshots` → `rollupAll()`.
2. **Rollup пересчитывается сразу** после снапшота (дёшево): суточные из часовых, месячные из суточных.
   Поэтому данные в окне AI не «ждут» полуночи.
3. **При старте сервера** — первый тик сразу (догоняет пропущенный час уже на следующем тике интервала).
4. **Полнота сутки**: день считается «полным», если в нём ≥20 часовых снапшотов (`fullDays` в `/api/ai/state`).
5. **Ничего не чистится** — база растёт: час → сутки → месяц.

## 4. API

| Endpoint | Что отдаёт |
|---|---|
| `GET /api/ai/state` | прогресс: `{hourly:{count,first,last}, daily:{...}, monthly:{...}, fullDays, nextHourAt, perSymbol}` |

## 5. Контракт AI-кода

Файл: **`components/ai/engine.ts`**, вход `AiInput` (прогноз + метрики + топ-аналоги + размер базы + бэктест),
выход `AiVerdict | null`:

```ts
{ verdict: "UP" | "DOWN" | "FLAT", confidence: 0..100, summary: string, tags: string[] }
```

`null` = движок не подключён (окно AI так и покажет). `summary` — 1–2 предложения **только из входных чисел**.
После подключения ключей — см. `env.example` (`.env.local`, в git не попадает).

## 6. Промт для модели (готовый)

Системный промт, который нужно передать модели вместе с JSON-входом из `AiInput`:

```
Ты — осторожный крипторынковый аналитик внутри образовательного дашборда.
На вход ты получаешь JSON: прогноз ансамбля (probUp/probDown/probFlat, confidence),
метрики (rsi, волатильность, fear&greed, дисбаланс стакана, funding, ΔOI),
топ-аналогов истории (label, sim, r7d), размер накопленной базы (hourly/daily/monthly/fullDays)
и историческую точность бэктеста (hitRate, baseline).

Правила:
1. Ссылайся ТОЛЬКО на числа из входа. Ничего не выдумывай, никаких нових фактов, дат и новостей.
2. Ответ — строго JSON без markdown: {"verdict":"UP|DOWN|FLAT","confidence":0-100,"summary":"...","tags":["..."]}
3. confidence ≤ min(confidence ансамбля×100, 90). Если base.fullDays < 1 или |probUp-probDown| < 0.08
   или hitRate ≤ baseline — verdict "FLAT", confidence ≤ 40, в tags добави "мало данных" / "нет.edge".
4. summary — 1-2 фразы по-русски, формат: «Что показывает (цифры) → вывод». Пример:
   «Аналоги склоняются вверх (32/50, 7д), но funding положительный и RSI 17 — разворот не исключён.»
5. Помни: прогноз — вероятность, не гарантия. Тон — сдержанный, без призывов «покупай/продавай».
6. Если данных недостаточно (мало hourly/daily/monthly) — честно пиши об этом в summary.
```

Замена «числа из входа» на данные за сутки/месяц происходит автоматически: перед `runAI`
можно подмешать `aiSeries(symbol, "daily" | "monthly")` — поля совпадают по смыслу.

## 7. Честность

- Часовые снапшоты — это **будущие** наблюдения: правдивость hitRate/baseline становится известна только спустя горизонт прогноза (7 дней). Поэтому в сводках hitRate — «последнее известное на момент снапшота».
- Накопитель ничего не «предсказывает» — он только фиксирует состояние; прогноз считает `lib/analyze.ts`.
- Образовательный проект. Не является инвестиционной рекомендацией.
